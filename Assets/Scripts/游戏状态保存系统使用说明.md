# 游戏状态保存系统使用说明

## 概述

本系统实现了完整的游戏状态保存和恢复功能，包括：
- 关卡内所有物体的显隐状态
- Highlight脚本的启用/禁用状态
- 广播历史记录
- 可用字符串列表
- 当前季节状态
- 收集的字符串列表

## 核心组件

### 1. GameStateManager（游戏状态管理器）

**功能：**
- 自动保存和恢复游戏状态
- 跨场景持久化的单例模式
- 支持手动保存/恢复/清除状态

**主要方法：**
- `SaveGameState()` - 保存当前游戏状态
- `RestoreGameState()` - 恢复游戏状态
- `ClearGameState()` - 清除保存的状态
- `ExitGameWithSave()` - 退出游戏前保存状态

**自动保存时机：**
- 应用失去焦点时
- 应用暂停时
- 手动调用时

### 2. ExitGameManager（退出游戏管理器）

**功能：**
- 处理退出游戏的逻辑
- 显示退出确认对话框
- 集成游戏状态保存功能

**主要方法：**
- `OnExitButtonClicked()` - 退出按钮点击事件
- `OnConfirmExitClicked()` - 确认退出事件
- `ExitGameWithSave()` - 退出并保存状态

**输入支持：**
- ESC键退出游戏
- Alt+F4退出游戏（Windows）

### 3. 扩展的BroadcastManager

**新增方法：**
- `GetBroadcastHistoryCopy()` - 获取广播历史副本
- `SetBroadcastHistory()` - 设置广播历史（用于恢复）

## 使用方法

### 1. 在场景中设置

**GameStateManager：**
1. 创建空的GameObject
2. 添加 `GameStateManager` 脚本
3. 设置调试选项（可选）

**ExitGameManager：**
1. 创建UI退出按钮
2. 创建退出确认对话框
3. 添加 `ExitGameManager` 脚本
4. 在Inspector中设置UI引用：
   - `exitButton` - 退出按钮
   - `confirmationDialog` - 确认对话框
   - `confirmExitButton` - 确认退出按钮
   - `cancelExitButton` - 取消退出按钮

### 2. 代码集成

**手动保存状态：**
```csharp
// 在需要的时候手动保存
if (GameStateManager.Instance != null)
{
    GameStateManager.Instance.SaveGameState();
}
```

**手动恢复状态：**
```csharp
// 在需要的时候手动恢复
if (GameStateManager.Instance != null)
{
    GameStateManager.Instance.RestoreGameState();
}
```

**退出游戏：**
```csharp
// 通过ExitGameManager退出（推荐）
ExitGameManager exitManager = FindObjectOfType<ExitGameManager>();
if (exitManager != null)
{
    exitManager.OnExitButtonClicked();
}

// 或者直接调用GameStateManager
if (GameStateManager.Instance != null)
{
    GameStateManager.Instance.ExitGameWithSave();
}
```

### 3. UI设置示例

**退出按钮设置：**
```csharp

}
```

**确认对话框设置：**
```csharp

Button confirmButton = // 确认按钮
Button cancelButton = // 取消按钮

```

## 保存的数据类型

### 1. 物体状态
- 物体名称和路径
- GameObject激活状态
- 位置信息
- Highlight组件状态
- SpriteRenderer组件状态

### 2. 游戏数据
- 广播历史记录
- 可用字符串列表
- 当前季节（Level3）
- 收集的字符串列表

### 3. 场景信息
- 关卡名称
- 保存时间

## 存储机制

### 1. 数据格式
使用JSON格式存储，通过PlayerPrefs保存到本地。

### 2. 键名规则
- `GameState_[关卡名]` - 主要游戏状态
- `BroadcastHistory_[关卡名]` - 广播历史
- `AvailableStrings_[关卡名]` - 可用字符串
- `CurrentSeason_[关卡名]` - 当前季节
- `CollectedStrings_[关卡名]` - 收集的字符串

### 3. 数据恢复
- 场景加载时自动检查是否有保存数据
- 延迟0.5秒恢复，确保场景完全加载
- 按顺序恢复：物体状态 → 广播历史 → 可用字符串 → 季节 → 收集字符串

## 调试功能

### 1. Context Menu测试
在Inspector中右键点击脚本，可以使用以下测试功能：

**GameStateManager：**
- "显示当前状态" - 显示当前状态信息
- "手动保存状态" - 手动保存状态
- "手动恢复状态" - 手动恢复状态
- "清除保存状态" - 清除保存的状态

**ExitGameManager：**
- "测试退出游戏" - 测试退出功能
- "强制退出游戏" - 强制退出（不显示确认对话框）

### 2. 调试日志
所有关键操作都有详细的调试日志输出，包括：
- 保存/恢复的数据量
- 物体状态变化
- 错误信息

## 注意事项

### 1. 性能考虑
- 物体状态收集可能较耗时，建议在非关键时机保存
- 广播历史恢复会重新发送所有广播，可能触发连锁反应

### 2. 兼容性
- 与现有的LevelProgressManager完全兼容
- 不影响原有的关卡进度保存功能
- 支持多关卡独立保存

### 3. 数据一致性
- 保存前会检查所有必要的组件是否存在
- 恢复时会验证数据有效性
- 支持部分数据缺失的情况

## 扩展功能

### 1. 添加新的保存数据类型
在 `GameStateData` 类中添加新字段，并在相应的方法中处理。

### 2. 自定义保存时机
重写 `OnApplicationPause` 和 `OnApplicationFocus` 方法。

### 3. 数据压缩
对于大量数据，可以考虑使用压缩算法。

## 故障排除

### 1. 状态未保存
检查：
- GameStateManager是否正确添加到场景
- 是否在正确的时机调用保存方法
- 检查Console中的错误日志

### 2. 状态恢复失败
检查：
- 保存的数据是否完整
- 场景中的物体名称是否发生变化
- 必要的组件是否存在

### 3. 退出功能不工作
检查：
- ExitGameManager的UI引用是否正确设置
- 退出按钮的事件绑定是否正确
- 检查Console中的错误日志

## 最佳实践

1. **在关卡开始时**：确保GameStateManager存在
2. **在重要操作后**：手动保存状态
3. **在退出前**：总是调用ExitGameWithSave()
4. **测试时**：使用Context Menu功能进行调试
5. **发布前**：关闭调试日志以提高性能
